# OKA

Сайт для проверки кассовых видео собственной моделью Qwen3-VL-8B. Интерфейс основан на [AmirBro0/1](https://github.com/AmirBro0/1), исходный дизайн сохранён. Подключены AI-сервис команды, подробные отчёты и API по кейсу ForteBank.

Пользователь вводит ключ, загружает **оригинальный MOV**, следит за статусом и получает вердикт, возможные нарушения, таймкоды и исходные JPEG. Отчёт показывает причины неопределённости и её влияние на вердикт, известные начало/момент/конец и нормативные основания. Подробный JSON скачивается отдельно от компактного ответа для жюри.

## Запуск сайта на Windows

Требуется Python 3.11+. В PowerShell из папки проекта:

```powershell
.\connect-server.ps1
.\start.ps1
```

Первый скрипт запрашивает адрес **нашего API**, например `http://127.0.0.1:8765`, и ключ со скрытым вводом. Настройки сохраняются в игнорируемом Git файле `.env`. Этот же ключ используется для входа на сайт. Второй скрипт устанавливает зависимости и запускает [localhost:8000](http://127.0.0.1:8000). При готовом окружении установка не повторяется.

URL JupyterLab или кабинета Brev не является URL анализа. Для удалённого GPU используйте доступный адрес API через HTTPS, VPN или SSH-туннель. Сайт не отправляет видео в сторонние AI API. Сервер Qwen может находиться рядом с сайтом, на сервере команды или во внутренней сети банка.

Для разных ключей: `API_KEY` — вход на сайт и API жюри, `DATATHON_API_KEY` — соединение с моделью. Браузер не получает ключ GPU. Пустой `DATATHON_API_KEY` использует `API_KEY`.

## Запуск нашей модели

Код находится в `engine/`: снимок рабочего конвейера Datathon, а не заглушка. Веса, видео, Excel с эталонами, кэши и секреты в репозиторий не включены. Модель не читает Excel с ответами.

Нужны отдельное GPU-окружение, CUDA, локальные веса **Qwen3-VL-8B-Instruct**, `yolo11n.pt`, `yolo11n-pose.pt`. Текущий сервис загружает Qwen в BF16, как на сервере H100. Маленькую видеокарту ноутбука этот запуск автоматически не поддерживает. Зависимости — `engine/requirements.txt`; не устанавливайте их в окружение сайта.

На GPU-сервере из `engine/`, с заданным секретом `DATATHON_API_KEY` в окружении:

```bash
python -m peoplewatch.service \
  --root /srv/oka/jobs \
  --model /srv/oka/models/Qwen3-VL-8B-Instruct \
  --yolo /srv/oka/models/yolo11n.pt \
  --pose /srv/oka/models/yolo11n-pose.pt \
  --decision-mode best_effort --host 127.0.0.1 --port 8765
```

`GET /health` с `X-API-Key` возвращает `ready: true` после загрузки весов. Сайт проверяет это через `/ui/v1/model-health` и показывает подключение. Пользователь передаёт исходное видео; кадры готовятся внутри конвейера. После установки зависимостей и весов сервис работает без интернета, оба процесса общаются по loopback или локальной сети. Звук и идентификация лиц не используются.

## API жюри

```bash
curl -X POST http://127.0.0.1:8000/api/v1/analyze \
  -H "X-API-Key: <ваш ключ>" -F "file=@video.mov"
curl http://127.0.0.1:8000/api/v1/jobs/<job_id> -H "X-API-Key: <ваш ключ>"
```

POST возвращает `job_id`. Статусы: `processing`, `done`, `failed`. Итоговый контракт:

```json
{
  "job_id": "…", "status": "done", "verdict": "violation",
  "violations": [{
    "type": "possible_cash_split_unresolved", "timecode_sec": 12.34,
    "description": "Описание видимого момента и основания проверки",
    "evidence_frames": [{"timestamp_sec": 12.34, "image_base64": "<JPEG base64>"}]
  }]
}
```

`no_violation` означает, что модель не обнаружила нарушение в проверенных наблюдениях. Это не гарантия отсутствия нарушения. Неопределённость, влияющая на вердикт, отражается как возможное нарушение; остальные вопросы сохраняются отдельно. Ошибка модели, связи, формата или таймаут даёт `failed`, а не чистый вердикт. Применимость юридической нормы не превращается в подтверждённую без проверки. На UI доступны оба обязательных текста вердикта из кейса.

Событие содержит 1–3 JPEG модели, содержимое и время не подменяются. Неизвестные границы эпизода показываются как «не установлено». Интервал дополнительной проверки не объявляется доказанной длительностью нарушения. Уверенность в процентах не выдумывается.

## Данные, очередь и развёртывание

- `data/` хранит SQLite, исходные видео и отчёты. Архив **общий для владельцев одного ключа**, не индивидуальный аккаунт каждого посетителя. Для независимых клиентов нужны отдельные установки/ключи или дальнейшая изоляция пользователей.
- По умолчанию MOV до 256 МБ, длительность до 180 с, один worker, очередь до 2 задач. Общий бюджет — до 300 с с очередью. Дедлайн ограничивает ожидание, но не гарантирует успешный анализ любого ролика за 300 с.
- Ключ не записывается в JS, URL, снимки конфигурации и отчёты. Авторизация UI использует HttpOnly SameSite cookie. При HTTPS cookie имеет флаг Secure.
- Сайт запускается на loopback. Для публичного URL нужен HTTPS reverse proxy с лимитом загрузки и защитой сервера; GitHub Pages не запускает Python backend. Ключи и видео не публикуются вместе с сайтом.
- Docker: `docker compose -f compose.datathon.yaml up --build -d`. Задайте URL модели, доступный **из контейнера**. `127.0.0.1` внутри контейнера не указывает на хост. Порт сайта опубликован только на loopback хоста.
- Старый детектор перекрытия камеры включается явно через `ANALYSIS_BACKEND=local`. В режиме `datathon` он не заменяет Qwen при сбое. Старый автономный Compose описан в `docs/legacy-local-detector.md` и требует `ANALYSIS_BACKEND=local`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют авторизацию, очередь, хранение, сохранность оригинального видео, HTTP-соединение с моделью, JPEG/таймкоды, подробные поля и ошибки. Ответы тестового HTTP-сервера синтетические и проверяют контракт, а не качество Qwen. Отдельный реальный прогон на GPU: `qa/gpu_integration.py`, только явный запуск, не обычный CI.

Соответствие требованиям и ограничения: [docs/forte-requirements.md](docs/forte-requirements.md). Развёртывание сайта само по себе не повышает accuracy. Лицензии весов, детекторов и оформления необходимо учитывать при коммерческом развёртывании; интеграция не меняет условия их лицензий.
