# oko

Приложение объединяет Minecraft-интерфейс oko с анализом OKO. Есть Overworld, рабочий Nether, End-архив, сохранённые видео и отчёты, таймлайн, кадры-доказательства, каталог норм и API для жюри.

## Запуск на Windows

Нужен Python 3.11 или новее. Открой PowerShell в этой папке и выполни:

    .\start.ps1

Скрипт создаст локальное окружение и установит зависимости при первом запуске. Страница: http://127.0.0.1:8000/. Ключ находится в API_KEY файла .env; setup.ps1 создаёт его, если файла ещё нет, и сохраняет существующие настройки. Ключ не вшит в страницу и не входит в архив проверок.

Другой порт:

    .\start.ps1 -Port 8765

Из уже подготовленного Python-окружения:

    python -m app --port 8000

Один локальный процесс запускает API и внутренний обработчик. Для этого нужен EMBEDDED_WORKER=1. Не запускай несколько Uvicorn workers с внутренним обработчиком. Отдельное контейнерное развёртывание: .\start.ps1 -Docker. Compose отключает внутренний worker API и запускает один отдельный обработчик без сети.

## Что действительно анализируется

По умолчанию работает obstruction — эвристический детектор перекрытия или сильного затемнения камеры, V13. Для него не нужны веса модели. Каталог содержит 21 тип, но наличие записи в каталоге не означает готовый детектор этого типа.

Модель команды подключается через model/model_runtime.py, старый контракт stdin/stdout сохранён. После реализации predict и установки зависимостей включи ENABLE_TEAM_MODEL=1. В имеющейся заготовке predict не реализован. Сервис не создаёт вымышленные нарушения, confidence или фиктивный отрицательный результат вместо ошибки модели.

Коды двух исходных событий FORTE сопоставляются с V06 и V05. Модель также может вернуть event_type из каталога V01–V20/X00. Числовой confidence необязателен; если модель его не дала, интерфейс не изображает измеренную уверенность. Ссылки и объяснения берутся из каталога, а не генерируются моделью.

Детектор перекрытия может реагировать на выключенный свет. Лица пикселизируются при обнаружении, но Haar cascade ненадёжен при виде сверху. Измеренная точность на банковском датасете не заявляется: датасет и веса не предоставлены.

`no_violation` в компактном API означает, что работавшие детекторы не вернули подходящих эпизодов. При стандартной конфигурации это относится только к V13 и не означает, что проверены все кассовые нарушения. Приватный API дополнительно возвращает `analysis_scope`: метод проверки, известные проверяемые коды, ограничения и подписи вердикта. Новые отчёты сохраняют эту область вместе с результатом; включение другой модели позже не меняет смысл прежней проверки. Для старых отчётов без сведений о детекторах область остаётся неизвестной. Само наличие команды внешней модели не доказывает её работоспособность или охват правил.

## Работа с проверками

1. Введи ключ и перейди в «Анализ».
2. Выбери видео и запусти анализ. Этапы, очередь и ограничения видны на странице.
3. Результат и управляемая копия видео сохраняются на сервере.
4. «Убрать видео» очищает только рабочее окно. Уже принятая задача продолжает работу в истории.
5. «История» открывает End. Поиск, фильтры, дата, просмотр человеком и отдельные запуски доступны в списке.
6. Открытие проверки восстанавливает её видео, отчёт, позицию и просмотренные эпизоды без нового анализа.
7. «Анализировать снова» создаёт самостоятельный запуск. Случайные повторные доставки одного запроса не создают второй запуск.

«Просмотрено» относится к просмотру человеком, а не подтверждению правонарушения. Низкоуверенные эпизоды review отделены от статуса просмотра. Ошибка анализа не означает отсутствие нарушений.

В End отдельный нижний портал открывает необязательные титры. Есть пропуск, пауза, Escape и reduced motion. Обычная навигация домой обходит титры. START ANALYSIS после возвращения использует действующую сессию.

## Хранение и доступ

Метаданные находятся в DATA_DIR/jobs.sqlite3, бинарные видео — в DATA_DIR/assets, промежуточные готовые результаты — в DATA_DIR/staged. VideoAsset может использоваться несколькими AnalysisRun. Удаление одного запуска не удаляет общий файл, пока он нужен другому запуску или активному чтению.

Архив локален для этого развёртывания; облачной синхронизации нет. Это общий приватный архив пользователей, имеющих ключ сервиса, без отдельных аккаунтов. Сессия HttpOnly, SameSite=Strict. Видео выдаётся защищённым маршрутом с поддержкой Range/HEAD, ключ в URL не передаётся.

UI-проверки сохраняются до явного удаления; старый TTL не стирает их молча. Временные запросы API жюри не перечисляются в пользовательском архиве, их оригиналы могут удаляться после обработки, а метаданные очищаются по RETENTION_HOURS.

Ошибка сохранения не запускает модель повторно: готовый staged-отчёт остаётся доступен для «Повторить сохранение». При полной недоступности диска/утрате самого каталога данных долговечное хранение невозможно; резервное копирование DATA_DIR остаётся обязанностью владельца развёртывания.

При запуске схема старой SQLite расширяется без удаления отчётов. Старые OKO JSON импортируются из DATA_DIR/jobs/*/api.json и ui.json. Для переноса другой папки OKO скопируй её jobs в DATA_DIR/jobs перед запуском, сохранив оригинал. Утраченные видео помечаются «Видео недоступно», отчёт остаётся доступен. Прерванное серверное вычисление получает честный статус; открытие истории не запускает его заново.

## API

Оба метода требуют X-API-Key:

    POST /api/v1/analyze
    multipart/form-data: file

    GET /api/v1/jobs/{job_id}

POST отвечает HTTP 200: job_id, status=processing. Статусы ответа GET: processing, done, failed. Готовый ответ содержит verdict=violation|no_violation и violations. Эпизод: type, timecode_sec, description, evidence_frames. Кадр: timestamp_sec, image_base64. Строгий API не добавляет UI-поля.

Idempotency-Key позволяет безопасно повторить один запрос. Для намеренного нового анализа нужен новый ключ. Один ключ с другим видео/конфигурацией возвращает 409; переполненная очередь — 503.

Закрытые /ui/v1/* обеспечивают сессию, расширенный отчёт, каталог, список запусков, видео, review, повтор сохранения и удаление. Клиент использует эти маршруты через единый адаптер. Справка API и норм доступна в интерфейсе.

## Настройки

- Форматы, максимальный размер и длительность: единые capabilities; значения MAX_UPLOAD_MB и MAX_VIDEO_SECONDS.
- Бюджет задания с очередью: OKO_DEADLINE_SEC, по умолчанию 240 секунд. Анализ запускается в завершаемом дочернем процессе; резерв — OKO_RESERVE_SEC.
- Кадры и пороги: OKO_SAMPLE_FPS, OKO_THRESHOLD, OKO_REVIEW_THRESHOLD.
- Музыка, эффекты, частицы и титры: web/config.js.
- Текст титров: web/content/credits.json.
- Графика трёх миров и маски частиц: web/worlds.js.
- Срок сессии: SESSION_HOURS.
- API_KEY и ENABLE_TEAM_MODEL меняются на сервере, без помещения в frontend или экспорт.

Подключены пользовательские треки Overworld, Nether, End и титров. End использует end.m4a на 8%, титры — titles.m4a на 10%; более тихая пользовательская настройка сохраняется. Overworld/Nether и приглушение во время видео работают как раньше. Звук включается кнопкой динамика. Сохранены прежние композиции трёх фонов; мелкая фактура усредняется до 480×270 с пиксельным масштабированием. Насыщенность/яркость только фона: Overworld 92%/97%, Nether 78%/88%, End 55%/82%; поверх — спокойные нейтральные наложения. Альтернативный overworld-soft.png сохранён и не используется. Существующий приватный Minecraft-пакет выключен по умолчанию и не включается в переносимую сборку.

## Проверки

    python -m pip install -r requirements-dev.txt
    python -m pytest -q

Настоящий сквозной прогон API:

    python scripts/make_test_video.py --out test.mov --cover 3:6
    python scripts/smoke_test.py --url http://127.0.0.1:8000 --key <ключ> --file test.mov --parallel 5

Браузерные проверки: qa/integration_browser.py. Они используют отдельный тестовый сервер/каталог, реальные синтетические видео и явно отличают тесты интерфейса с перехватом ответов от настоящего анализа. Итог текущей проверки фиксируется в INTEGRATION_REPORT.md. Проверки на датасете: scripts/eval_labels.py; ошибки обработки не считаются отсутствием нарушений.

В Docker-сборке для внешней модели предусмотрены FFmpeg и системные зависимости OpenCV. Контейнерную сборку нужно отдельно проверить на машине с Docker; Windows-запуск V13 не требует отдельного FFmpeg. Источники ресурсов перечислены в ASSET_MANIFEST.json и ASSETS.md.
