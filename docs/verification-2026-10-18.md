## Автоматические проверки сайта

71 тест пройден. Проверены авторизация, сессии, архив, API жюри, работа очереди, сохранность оригинального видео при передаче через HTTP, события и подробные данные модели, JPEG, таймкоды, ошибки, отсутствие ключа модели в ответах и снимках конфигурации. Тесты нового моста используют синтетический ответ сервера: это проверка контракта, не accuracy.

Проверен синтаксис изменённых JavaScript-модулей и трёх PowerShell-скриптов. `git diff --check` без ошибок.

## Браузер

В локальном браузере выполнены вход по ключу, выбор MOV, отправка через форму, получение и восстановление отчёта после перезагрузки, просмотр таблицы моментов и нормативного основания, переход к моменту, скачивание подробного JSON. Скачанный файл прочитан: подробные поля и предварительный статус сохранились. Ошибок JS в журнале не найдено.

Для MOV с неподдерживаемым браузером кодеком доступен ближайший сохранённый JPEG; подпись показывает фактический таймкод этого JPEG, а не выбранное время ползунка.

Отображение таймкодов сохраняет миллисекунды ответа вместо обрезания до десятых; 6 проверок форматирования, включая переход минуты, пройдены. Количество знаков не означает такую же точность обнаружения события.

## Исправление подключения и реальный повтор Х-17

Сайт был настроен на локальный порт без сервиса Qwen. Подключение этой установки переключено на уже существующий HTTPS API своего NVIDIA H100 с действующим служебным ключом; пользовательский ключ сайта сохранён. На GPU запущен ранее проверенный снимок `oka-integration-01/engine` в режиме `best_effort`. Сервис оформлен как `oko-model.service`: автозапуск после перезагрузки и перезапуск после аварийного выхода. Действующие задания перед заменой сервиса отсутствовали. Секреты и адрес конкретной установки не включены в коммит.

Сайт обновляет статус модели каждые 10 секунд и перед отправкой. При недоступности модели запуск заблокирован, выбранное видео остаётся в окне. Серверные маршруты нового анализа и повторного анализа возвращают HTTP 503 без создания задания. Идемпотентное восстановление уже принятого запроса работает даже при недоступном Qwen. Ошибка служебного ключа не требует повторного входа посетителя. Скрипт подключения сначала проверяет API и сохраняет прежний ключ пользователей.

Проверки: **76 тестов Python пройдены**, синтаксис JavaScript и PowerShell корректен. В отдельном браузерном стенде проверены состояния `ready=false` → `ready=true` → ответ другого сервиса → `ready=true`: кнопка запуска блокируется и восстанавливается автоматически без повторного выбора файла. Стенд возвращал только состояние готовности, не имитировал результат анализа.

Через кнопку «Проверить снова» в истории рабочего сайта отправлен сохранённый оригинальный **Х-17.mov**. Реальный Qwen на H100 завершил анализ, сайт сохранил результат: `done`, предварительный `no_violation`, 6 оценок моментов, **165,18 с** с очередью. Это подтверждает работу подключения и полного пути видео → модель → отчёт, **не измеряет accuracy и не доказывает правильность вердикта**. Аудит без кадров и секретов: [qa/connection-repair-X17.json](../qa/connection-repair-X17.json). Предыдущая неудачная проверка сохранена в истории отдельно.
